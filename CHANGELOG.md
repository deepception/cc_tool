## v0.0.16

Fable 5.1 re-baseline plus a prompt-cruft audit of every text surface that reaches the model. The audit ran the bundled `/claude-api prompt-audit` flow over the managed block, the template, all 20 skills, the three workflow scripts, the hooks' model-facing strings, and the README's routing section, with the target model set to Claude Fable 5.1 (`claude-fable-5-1`) and Opus 5 kept as the default every rewrite must still fit. 27 findings: 5 high, 14 medium, 8 low. All high/medium items were applied; the 8 low-confidence flags (the "Critical rules" heading, the no-fabrication rules, effort guidance addressed to a model that cannot change its own effort, a volatile token-reduction figure in `knowledge-wiki`, the 200-line / 1,536-char caps in `skill-engineer`) were left as-is by design. Every claim about Fable 5.1 below was checked against the official "What's new in Claude Fable 5.1" and "Prompting Claude Fable 5.1" pages, and the harness facts against the installed CLI (2.1.258).

- **Half-landed migration finished.** The managed block had moved to `claude-fable-5-1` while README, `dynamic-workflows`, `ship-pipeline.js`, and the block's own Cost-guard bullet still said Fable 5 was "rarely worth it" — two projects reading the same setup got opposite routing advice. All four now carry one position, in Anthropic's own framing: Opus 5 for most workloads; Fable 5.1 for demanding reasoning and long-horizon agentic work (multi-hour coding sessions, multistep research, document/spreadsheet/slide deliverables, dense-chart vision) or when Opus 5 at higher effort still falls short. New routing fact: Fable 5.1 cache reads are $0.25/MTok, half Opus 5's $0.50, so long cache-heavy Claude Code sessions narrow the 2x gap.
- **Refusal guidance corrected.** Finding vulnerabilities in source is permitted on both models; the three documented false-positive triggers are named (compile-check phrasing, lesser-known languages without context, base64 in tool output). Fallback direction fixed: a Fable refusal lands on Opus 5; an Opus 5 cyber refusal lands on Opus 4.8. The earlier "compile-check wording" phrase, which had no referent, is replaced by the docs' example pair.
- **Two harness facts stale in every managed project** — the block told Claude to invoke Superpowers skills "by reading the skill file" (the installed skill itself says: Skill tool, never Read) and named the subagent tool `Task` (it is `Agent`). Both fixed.
- **Opus-5-era clamps removed for Fable 5.1**, each traceable to a CHANGELOG entry that named the model it patched: "no preamble" (Fable 5.1 under-narrates; the docs ask for an opening line before tool work, which the block now requests alongside the closing recap); "Delegate sparingly" / "Do not delegate" from v0.0.12's Opus 5 over-delegation fix (Fable 5.1 is documented as strong at parallel sub-agent work — the criterion stays, the clamp goes, so it still holds on Opus 5); the "weigh at least two approaches / decompose into sub-questions" reasoning choreography left over from v0.0.9's 5-phase protocol (always-on adaptive thinking plans natively; numeric choreography over-plans).
- **Fable 5.1 behavior deltas absorbed** where they touch a Claude Code setup: surgical edits over whole-file rewrites (Minimal impact rule), own-words summaries with reproduced passages marked as quotations (Output discipline docs paragraph and `knowledge-wiki` ingest), and "recognizing a name is not knowing its current state" for model ids, versions, flags and APIs (No fabrication rule). Deliberately not added: forced-tool-use, thinking-binding, per-message effort, turn-scoped system messages and `display: "updates"` are API features Claude Code manages itself; the tool-call batching nudge is a per-turn harness injection; the autonomy prompt is already injected by the harness in non-interactive mode.
- **Duplicates and dead text in the managed block**: the "Recommended practice" bullets restated three table rows (folded into the table); rule 4 restated Reasoning approach and rule 7 restated Verification protocol (removed, rules renumbered 1–9); the Write/Select/Compress/Isolate context-engineering lecture and its "~15 steps" heuristic reduced to the instructions the model cannot derive itself. `CLAUDE_template.md` stated "run quality checks before committing" three times; once now.
- **Skills**: `skill-engineer` no longer teaches "no explanations of why — just what to do" (reasons beside constraints are what keep a rule from being applied where it doesn't fit; the line contradicted the skill's own plain-imperatives rule two bullets up); `design-an-interface` anti-pattern list trimmed to the two that weren't restating steps 2 and 4; `product-ui-motion`'s header comment keeps the MIT attribution and drops the correction log the model was re-reading on every trigger (it lives in v0.0.14's entry). The four "delegation cap" cross-references now say "delegation guidance", matching what Context management actually states.
- **Workflow prompts**: `model-recalibration-audit.js` loses its `CRITICAL:` / `DO NOT FABRICATE` / `ANTI-HALLUCINATION RULE` register, the grader vocabulary ("will be downgraded on review") and two "worked example from a prior run" anecdotes — the rules stay, stated as requirements; `loop-until-clean.js` schema and finder prompt likewise. `node --check` passes on all three scripts.
- **README split.** 395 lines → a 90-line front door (pitch, quick start, what you get, commands, model choice, day-to-day use, guide index). The deep-dive sections moved verbatim to [`docs/guides/`](docs/guides/) — sandboxing, vault, design, app-qa, workflows + unattended runs, commands in detail, directory layout — with `docs/*` now ignored except `!docs/guides/`. Match ⇒ the copy is an untouched older release and is refreshed; no match ⇒ it carries local edits, is left alone, and is named in the output. Local *additions* inside a refreshed skill survive; files cc_tool shipped and later dropped are removed. Measured on the three projects that had been on 0.0.11 since 2026-07-09: **11 stale skill directories each**, four of them still pre-0.0.11 (`design-an-interface`, `dynamic-workflows`, `skill-engineer`, `skills-audit`) — i.e. every skill edit since v0.0.6 had been silently failing to reach them. Re-runs settle at `refreshed 0, already current 16`; an earlier iteration re-reported a skill with a local extra as "refreshed" forever and was fixed before shipping. README corrected in three places that documented the skip.
- **`CLAUDE_snippet.md`** — one routing paragraph in the managed block (the channel that reaches already-configured projects): product-UI motion goes to `product-ui-motion` in new code and existing apps alike, dashboards included, and it outranks the taste skills on duration, easing and `transition` shorthand.
- **`frontend-review`** — new **dimension 9, "Motion & interaction feel"**, reading the same catalog via `../../product-ui-motion/` rather than duplicating it (the cross-skill reference pattern `ui-ux-review` already uses for `driving-tools.md`, with the same not-installed hedge). - **README** — skills tree entry, the 9-dimension count, and a paragraph in the design section covering what the new skill owns and why it supersedes the taste skills at product scale.

## v0.0.12

Claude Opus 5 recalibration, lineup narrowing, and a de-bloating pass. Driven by parallel audits (Opus 5 recalibration, redundancy, anti-slop, hooks, skills), each adversarially verified before anything shipped — the verification pass refuted 2 findings, downgraded 2 more, and caught a P0 the original audit missed.

**Every surface you actually pay for shrank**, even though an output-discipline layer was added: the managed `CLAUDE.md` block (resident in every session of every project) went 167 → 146 lines, the README 397 → 373, `bin/cc-setup` 290 → 211. Total repo size grew — the hardened `bash-guard.py`, the vendored `no-ai-slop` skill (164 lines), and this entry all add weight that never enters a session's context.

**The model lineup is now Opus 5 / Sonnet 5 / Fable 5 and nothing else.** Opus 4.8 and older are the same price class as Opus 5 with less capability; Haiku is unused. Opus 4.8 survives in exactly one place — the documented landing spot when Opus 5's cyber classifier declines a request — framed as a footnote, not a routing tier.

- **`context-usage.py` — the warning has been misfiring since v0.0.7, and both fixes for it were wrong before this one.** The allowlist matched only `opus-4-8`/`fable-5`, so Opus 5 sessions took the 200K floor and warned "80% full" at ~16% of a 1M window, every turn, in every managed project. Inverting it to a denylist then over-corrected: Opus 4.6 and Sonnet 4.6 serve 1M through the API but are configured at **200K in the harness**, so those sessions could never warn at all. The mapping is now an explicit `NATIVE_1M_FAMILIES` allowlist derived from the CLI's own shipped model registry — ground truth, not recall — with the `grep` that re-derives it recorded in the docstring, and an unknown model falling to 200K so a new model warns early rather than silently never firing. Verified against all 14 model ids in the registry plus harness/provider variants (18/18).
- **`bash-guard.py` hardened against bypasses found by execution, not reading** — 103/124 → **124/124** on a reconstructed matrix (102 original cases + 22 new), 21 verdict changes, all intended, zero regressions across a second 93-command real-world sweep. Fixed: `git push origin HEAD`/`@` allowed on `master`; global git options (`git -C`, `git -c`, `--git-dir`) skipping the commit check entirely; `--amend` and `--no-verify` matched as substrings (`git commit -m 'docs: explain --amend'` was allowed); `git commit -n`; `git -c core.hooksPath=/dev/null commit`; redirection and absolute-path secret reads (`grep KEY < .env`, `/bin/grep KEY .env`, `echo .env | xargs grep KEY`). **`git -C <path>` now resolves the branch in the targeted repo**, not the cwd. Superlinear parsing bounded: 51 KB input went from ~12s to under 0.1s against a 3s timeout. **Now fails closed** — an unparseable payload previously exited 1 and let the command through. Docstring gained a "WHAT THIS IS NOT" section naming the shell-expansion bypasses as inherent: it is defence-in-depth behind `permissions.deny`, not a sandbox.
- **New `## Output discipline` in `CLAUDE_snippet.md`** (213 words / ~1.3 KB, prose not checklist) — response length and shape, format-follows-content, concreteness, and the AI tells worth naming; extended to documents written to disk, which matters because ~7 skills emit docs and Opus 5 pads them the same way it pads chat.
