## v0.0.11

App-QA release — generalizes a hand-built QA engagement (an e2e test plan with walkthrough markers, a severity-tagged UI/UX review, and a static frontend review that duplicates neither) into four skills that reproduce it on any app type: web, API, CLI, TUI, mobile. The engagement's three documents were produced manually once (Opti-Plan UI, 2026-07-08); these skills carry the distilled formats. Execution mode is the user's choice per run: agent-driven (with detected browser/device tooling) or paired step-by-step with the user. Verified via subagent application tests against a fixture app (plan-format compliance, rubric application, no-duplication contract, orchestration dry-run) plus the skill-engineer validation checklist and a scratch cc-setup deploy.

- **New skill [`e2e-testing`](templates/skills/e2e-testing/SKILL.md)** — intake → driver detection (honest no-driver fallback: paired mode only, names what to install) → recon → `docs/E2E-TEST-PLAN.md` (scenario tables with hierarchical ids, §0 conventions/fixtures, P0–P2 tiers, ✅/❌/unmarked legend) → user plan approval → mode + scope choice → execution recording results in place (✅ only on observed result; ❌ carries symptom → evidence → root cause → fix → regression-test note inline) → wrap-up with fix order, automated-suite offer, and a `loop-engineering` pointer for recurring regression sweeps. References: [test-plan-format.md](templates/skills/e2e-testing/references/test-plan-format.md), [driving-tools.md](templates/skills/e2e-testing/references/driving-tools.md) (app-type → launch/driver/step/evidence table), [example-e2e-test-plan.md](templates/skills/e2e-testing/references/example-e2e-test-plan.md) (worked example: mid-walkthrough plan with ✅/❌ markers and a full inline bug entry).
- **New skill [`ui-ux-review`](templates/skills/ui-ux-review/SKILL.md)** — stated-baseline walkthrough (role/viewport/theme/locale/date), 🔴🟡🔵 severity rubric measuring user impact, beyond-happy-path sweep (both themes, ≤1280px, i18n leaks + diacritics, empty/loading/error states), mandatory "what already works well (keep)" section, severity-led fix order; adaptation table for CLI ("screen" = subcommand + `--help`) and API surfaces. Reference: [review-rubric.md](templates/skills/ui-ux-review/references/review-rubric.md).
- **New skill [`frontend-review`](templates/skills/frontend-review/SKILL.md)** — static interface-layer review under a two-rule contract: no duplication of sibling docs' findings (a catalogued finding reappears only with a new, distinct root cause) and honesty about limits (a closing "needs live confirmation" section). Eight dimensions (API client/auth plumbing, state management, component quality, i18n architecture, type safety, a11y basics, direct/indirect/none test-coverage mapping, build hygiene), every finding cited `file:line` and re-verified at its citation before writing. Subagent-friendly: no live app needed. Reference: [review-dimensions.md](templates/skills/frontend-review/references/review-dimensions.md).
- **New skill [`app-qa`](templates/skills/app-qa/SKILL.md)** — thin orchestrator over the three workers: deliverable multiselect, discovery once, `frontend-review` dispatched as a parallel background subagent while live testing runs, UI/UX observations collected during the e2e session plus a dedicated gap sweep, final reconcile (dedupe favors live docs) and one unified cross-doc fix order. Workers stay independently invocable.
- **`CLAUDE_snippet.md`** — new `### App QA & e2e testing` routing paragraph (managed block): full engagement → `app-qa`; single activity → its worker skill.
- **README** — new `### App QA & e2e testing` how-to section under How-to-work-with-the-setup (the `/app-qa` seven-step flow, standalone worker invocations, honest mode-offer rules incl. the Playwright-MCP install command, the loop-engineering re-run pointer); the four skills added to the manual-invocation list and the directory tree.

## v0.0.10

Self-writing vault + loop taxonomy release — distilled from two X articles: the Claude Code team's "Getting started with loops" (@delba_oliveira) and "The Self-Writing Vault: 8 Rules for Pointing Claude at Obsidian and Letting It Run Without You" (@chewadot). Fills the one knowledge niche the lineup lacked — the user's OWN raw thinking, per project, processed without the user — and gives `loop-engineering` the official pick-the-loop-type layer. Redundancy review outcome: no existing feature overlapped the vault niche, so nothing was removed; the sweep instead enforced single-sourcing on the new content (no fourth statement of the `/goal` anatomy — the taxonomy cross-refs "Safe autonomous loops"; the vault rules live once, in the scaffolded `vault/README.md`).

- **New [`bin/cc-vault`](bin/cc-vault)** — deterministic scaffolder (scripts, not tokens, for deterministic work — the loops article's own rule): creates `vault/{inbox,raw,notes,daily,synthesis}/` plus seeded `index.md` (routing table), `log.md` (append-only run ledger — the loop's disk state), `README.md` (the five-rule contract: single inlet, immutable `raw/`, ≥3 backlinks with ≥1 old, digest→synthesis, graph pulse), and `AUTOMATION.md` (three trigger wirings with the real project path substituted: system cron via headless `claude -p --model sonnet --permission-mode acceptEdits`, `/schedule` cloud routine, `/loop`). Idempotent; `--private` gitignores the vault without duplicating the entry; `--force` re-copies seeds. Seeds live in [`templates/vault/`](templates/vault/); `cc-setup --vault` chains to it. Verified: double run, `--private` re-run, path substitution, skill auto-copy via `cc-setup`.
- **New skill [`vault`](templates/skills/vault/SKILL.md)** — operations: `init` (delegates to `cc-vault`; manual fallback), `process` (empty inbox → cheap no-op so a daily trigger costs ~nothing; else move originals untouched to dated `raw/`, distill into `notes/` under the backlink invariant, update `index.md`, write the daily digest, append the ledger), `synthesize` (weekly, reads only the last 7 days: recurring themes, contradictions, half-made promises), `health` (report-only graph pulse: inbox backlog, orphans, link density vs the last logged baseline, index drift). Needs only Read/Write/Edit inside `vault/` — no ask-listed commands — so it survives headless `acceptEdits` runs; positioned as the shipped worked example of a *proactive loop*. Boundaries stated against `knowledge-wiki` (external corpus) and basic-memory (cross-project decisions).
- **`session-context.py`** — when `vault/inbox/` exists, injects one session-start line: unprocessed-inbox count + newest daily digest + newest synthesis (article rule 7, "context into every session" — pointers only, ~zero token cost). Verified against empty-inbox, populated, and no-vault projects.
- **`CLAUDE_snippet.md`** (managed block) — new `### Self-writing vault` capture-routing rule (mid-session "note this down" → new dated file in `vault/inbox/`, never into `notes/` directly, never edit `raw/`); the basic-memory/knowledge-wiki boundary sentence gains the vault as its third corner; the Safe-autonomous-loops caveat now includes reviewing the `/usage` breakdown.
- **Skill [`loop-engineering`](templates/skills/loop-engineering/SKILL.md) upgraded from the official loops article** — new "Pick the loop type" section: the four-type taxonomy table (turn-based / goal-based `/goal` / time-based `/loop`+`/schedule` / proactive) with trigger, stop condition, best-for, and usage lever per type ("pick the weakest that fits"); `/goal` evaluator mechanics (a separate evaluator model gates every stop attempt until criteria or turn cap — deterministic criteria beat judgment calls); proactive-loop-as-composition recipe (`/schedule` + `/goal` + workflow + auto mode) with the vault as the shipped example; new "Keeping a loop cheap" section (interval matched to the watched thing's change rate, pilot a slice first, deterministic steps in scripts, `/usage` / `/goal`-no-args / `/workflows` monitoring); the flywheel rule (encode a below-bar result back into the system — sharper verifier, CLAUDE.md convention, `reflect` — so future iterations inherit the fix); and the four-question adoption test appended to When-NOT (bottleneck? verification writable? goal crisp? scheduled arrival? — a "no" on verification is disqualifying).
- **README** — new "Self-writing vault" section under How-to-work-with-the-setup, `cc-vault` in the command list and directory structure, hook/skill listing lines updated.

## v0.0.6

Loops & multi-agent orchestration release — distilled from nine community X articles on Claude Code loops, dynamic workflows, and recursive agent calls, then adversarially verified (6-domain review + skeptic-per-finding) and design-debated (3 positions + judge per open question).

- **New skill [`dynamic-workflows`](templates/skills/dynamic-workflows/SKILL.md)** — teaches the native `Workflow` tool: the harness mental model (per-agent isolation/model choice; fixes agentic laziness, self-preferential bias, goal drift), the core API (`agent`/`parallel`/`pipeline`), the 6 orchestration patterns (classify-and-act, fan-out-and-synthesize, adversarial-verification, generate-and-filter, tournament, loop-until-done), composition, and operational controls (`/goal`, `/loop`, explicit token budgets, quarantine for untrusted input).
- **New skill [`knowledge-wiki`](templates/skills/knowledge-wiki/SKILL.md)** — Karpathy's compile-once "LLM Wiki" pattern: digest an external source corpus into a project-local `.wiki/` (raw snapshots + synthesized pages + index + log) and answer queries from the digest instead of re-reading raw files (~84-90% token reduction per the llm-wiki-compiler reference). Complements basic-memory (emitted decisions) — does not replace it. In-repo sources are cited by path, never duplicated into `raw/`.
- **Two worked-example workflows** (repo-local, templates to adapt — deliberately NOT installed into projects): [`ship-pipeline.js`](.claude/workflows/ship-pipeline.js) — Planner (Opus) → Coder (Sonnet) → Tester (Sonnet) → Reviewer (Opus) with schema'd handoffs, the coder report threaded into the read-only review gate, and a fail-fast guard on missing args; [`loop-until-clean.js`](.claude/workflows/loop-until-clean.js) — loop-until-done sweep (stop after two consecutive dry rounds, canonical dedup slugs normalized in plain code) + adversarial verification of survivors.
- **`CLAUDE_snippet.md` — orchestration & loop guidance** (managed block): a which-fan-out-mechanism decision table (`dispatching-parallel-agents` ~2–5 tasks / native `Workflow` for scale, loops, adversarial checks / Ruflo swarm for cross-repo or persistent swarm state / experimental agent teams for peer debate); model/effort routing on fan-out (cheap arms, Opus + `xhigh` for synthesis/verification); a **Safe autonomous loops** checklist (spec-first + `/goal`, bounded iterations, cost guard, no irreversible unattended actions, verification gate where the judge is never the worker); first-class notes on `/loop` and `/schedule`; basic-memory vs knowledge-wiki boundary; compile-once context principle.
- **Anti-fabrication layer** (from the "4-layer honesty setup"): new Critical rule **No fabrication** — never invent functions/methods/imports/flags/config keys/paths, confirm symbols before referencing, "I don't know" is rewarded; Verification protocol step 4 now requires the actual command + tail of its real output (a bare "tests pass" claim is a skipped step); `CLAUDE_template.md` mirrors the paste-output rule at the implementation checkpoint and points to the single-sourced No-fabrication rule (asymmetric dedupe per debate ruling).
- **New hook [`post-edit-typecheck.py`](templates/hooks/post-edit-typecheck.py)** (PostToolUse Edit|Write|MultiEdit) — fast project check after source edits (`tsc --noEmit` / `cargo check`; `ruff check` file-scoped), informational only, silent on success, never blocks; resolves project-local `tsc` first (no `npx` fallback — squatting risk), strips ANSI, handles `ruff.toml`-only projects; tsc timeouts back off for 30 min via a self-describing marker in `.git/` (cargo self-heals via incremental `target/`, so no marker). Registered in both `settings.json` and `hooks-config.json`.
- **`bash-guard.py` — secret-read guard**: denies Bash reads of secret material (`.env*`, key files, credential stores) via readers the file-Read deny rules can't see — `grep`/`awk`/`sort`/`cut`/`source`/`.`/`xargs`/inline `python -c`/`node -e` — with command-position gating for `.`/`source` and grep-family pattern-argument awareness (searching the codebase *for* ".env" is not reading `.env`). Verified against a 24-case allow/deny matrix; existing branch/push/`--no-verify` guards unchanged.
- **`settings.json` deny hardening**: bare env dumps (`env`, `printenv`, `set`, `export -p`; the old `printenv*AWS*`/`*GOOGLE*` pair is subsumed and removed); Azure / DigitalOcean / git-credentials / npmrc / pypirc / gnupg / shell-history credential stores; terraform state files + `Read(**/*secret*.tfvars*)` (narrowed from blanket `*.tfvars` per debate ruling — plain IaC config stays readable); Read-deny on `*.pem`/`*.key`/`id_rsa*` for symmetry.
- **README** — workflow pattern catalog + operational controls; **Unattended / autonomous runs** section (the `ask` list auto-denies in `claude -p` and stalls interactive loops — pre-resolve + pre-allowlist paired with `/sandbox`, or run in the devcontainer); native **`/sandbox`** section (literal-path deny rules gain OS-level teeth; Linux bubblewrap is literal-paths-only, macOS Seatbelt supports globs); accurate hook table (7 scripts).
- **`design-an-interface`** — sub-agents now ground designs in the project's interface vocabulary while explicitly preserving radical structural divergence per their assigned constraint.
